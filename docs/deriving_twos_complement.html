Deriving Two’s Complement

We represent non-negative numbers using bytes via the obvious scheme: padded binary. Under this scheme, bytes represent 0 to 255, and 00001100, say, represents 12. Other schemes are possible. But this one’s nice.

Given the scheme, call it \$b\$, we can make an adder circuit: it takes two bytes as input and outputs the byte which represents the sum (mod 256) of what they represent.

Fine, but what if we want to represent negative numbers too? Let’s pick a scheme, call it \$s\$, for that.

It would be nice if we could use the same adder circuit for \$s\$ as \$b\$. Then we wouldn’t need to build a new circuit or care about the scheme when dispatching sums to circuits. All sums would go to the adder. Also, because \$i - j = i + -j\$, we could use the adder for subtraction too.

To say we can use the adder for \$s\$ is to say:

\$s(w ** u) -= s(w) + s(u)\$

for any bytes \$w, u\$, where \$**\$ is the operation carried out by the circuit and \$-=\$ is congruence mod 256.

How far does this constrain \$s\$?

In what follows I sometimes identify bytes and what they represent given \$b\$, e.g. 00000011 and 3. Yes, it risks confusion to rely on \$b\$ when discussing \$s\$. But it should be clear enough what’s meant and it’s easier to write down numbers than bytes.

Now, \$s(0) = s(0 ** 0) -= s(0) + s(0)\$ so \$0 -= s(0)\$. Furthermore, \$s(2) = s(1 ** 1) -= s(1) + s(1) = 2 * s(1)\$, and so \$s(3) = s(2 ** 1) -= s(2) + s(1) -= 3 * s(1)\$, and so on. Thus: \$s(k) -= k * s(1)\$ for all \$k = 0, ..., 255\$. So settling \$s(1)\$ settles \$s\$ up to congruence.

The adder constraint alone gets us no further. Indeed, suppose \$s(k) -= k * s(1)\$ for \$k = 0, ..., 255\$. In other words, \$s(x) -= b(x) * s(1)\$ for every byte \$x\$. Then \$s(w ** u) -= b(w ** u) * s(1) -= (b(w) + b(u)) * s(1) -= b(w) * s(1) + b(u) * s(1) -= s(w) + s(u)\$. So the adder constraint and \$s(k) -= k * s(1)\$ are equivalent.

The adder constraint leaves \$s\$ pretty open: set \$s(1)\$ to any number you like, then for \$s(k)\$ pick any member of \$k * s(1)\$'s equivalence class mod 256. For example, we could set \$s(0) = 0, s(1) = 123, s(2) = 246, s(3) = 369, ...\$, or \$s(0) = 0, s(1) = 128, s(2) = 0, s(3) = 128, ...\$, or \$s(0) = 0, s(1) = 0, s(2) = 0, s(3) = 0, ...\$.

Let’s impose some natural further constraints.

We might insist that \$s\$ is injective: different bytes represent different numbers. That’s equivalent to \$s(1)\$ and 256 being coprime, i.e. \$s(1)\$ being odd.

Or we might insist that \$s\$ can represent 1, and uses the same byte as \$b\$ to do it, i.e. \$s(1) = 1\$. That implies \$s(k) -= k\$, which determines \$s\$ up to congruence. For example, we could set \$s(0) = 0, s(1) = 1, s(2) = 258, s(3) = -253, s(4) = 21252, ...\$.

Or we might insist that \$s(1) = 1\$ and \$s\$ represents a contiguous range of numbers. In that case, all we can choose is where to jump backwards by 256: immediately, giving \$s(1) = 1, s(2) = -254, s(3) = -253, ..., s(255) = -1, s(0) = 0\$; or some way along, giving e.g. \$s(1) = 1, s(2) = 2, ..., s(85) = 85, s(86) = -170, s(87) = -169, ..., s(255) = -1, s(0) = 0\$, or never, giving \$s(1) = 1, s(2) = 2, ..., s(0) = 256\$, (although that defeats the aim of finding a schema to represent negatives).

If we jump at 128 we get \$s(1) = 1, ..., s(127) = 127, s(128) = -128, s(129) = -127, ..., s(0) = 0\$, which has two nice properties: it’s centred at 0 and the high bit signals the sign. That’s two’s complement.

To summarize. How to pick a scheme \$s\$ for representing signed numbers as bytes? We want to re-use the adder, i.e. \$s(w ** u) -= s(w) + s(u)\$. But that only settles \$s\$ up to congruence after a free choice of \$s(1)\$. Choosing \$s(1) = 1\$, sensibly enough, gives \$s(k) -= k\$. Two’s complement is just a nice choice of representatives from the equivalence classes, giving a contiguous range centred at 0 with high bit signaling the sign.
